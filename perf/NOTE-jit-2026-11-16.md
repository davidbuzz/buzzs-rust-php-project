# The per-op native JIT experiment — measured, dead end (2026-11-16)

A native per-op interception layer over the tape (`jit.rs`, opt-in via
`PHPRUST_EXEC_MODE=jit`) compiled a straight-line run of bytecode ops between
loop-back jumps into a step table with per-site operand guards, and ran each
op natively with the interpreter as fallback. It was never committed; the
worktree copy was lost to a tree reset + clean before it could be. This note
records what it measured so the design does not have to be relitigated.

## Measured envelope (same release binary, JIT on vs off, 2M reps)

| workload | tape | JIT | verdict |
|---|---|---|---|
| micro:while (`$x = $x + 1; $y = $y * 2`, arith loop) | 40 /iter | 28 /iter | the only win: −30% |
| micro:strlen (`$l = strlen($s);` in a loop) | 42 /iter | 84 /iter | call-loop regression: +100% |
| zend:mandel | 1,004,585,997 | 1,004,590,033 | unchanged — body disqualified |
| zend:ary3 / matrix / sieve / heapsort / hash1 / hash2 / fibo | — | — | unchanged (bit-level) |
| zend:simplecall / nestedloop (already meeting) | 0.67 / 1.01 | 0.67 / 1.01 | unchanged |

Real workloads pay only the (negligible) compile attempt: their loop bodies
contain array reads, calls or abs, which the operand guards disqualify, so
the JIT runs nothing.

## Why it cannot flip any goal.tsv workload

1. The entry protocol is per-op, not per-function: every loop iteration
   re-enters through the interpreter (flags, ip save/restore, guards, epilogue
   ≈ 10–12 instructions per op-transition). micro:while's C baseline is
   17 instr/iter (goal ≤ 18.7); even the JIT's improved body runs ~12 + the
   loop jump ≈ 28 — still over. Reaching 15–20 needs whole-loop native
   codegen: enter once, run the loop natively, deopt on guard miss.
2. The C micro baselines are not dispatch-dominated — opcache specialises and
   hoists whole loop bodies. micro:strlen measures 15 instr/iter in C,
   *below C's own empty loop (30/iter)*: the invariant `strlen($s)` is hoisted
   and the dead body largely eliminated. Matching those rows needs
   loop-invariant hoisting + dead-loop elimination in our optimizer, not
   faster per-op dispatch.
3. Every guard that would capture the near-miss array rows (dim reads) is
   exactly the generic zval path again — the guards cannot beat our tape fast
   paths by enough to close 1.4–1.8x.

## Verdict

Closed. Do not rebuild the per-op interception design. If native codegen is
pursued again, the measurement says it must be whole-loop (per-function entry,
native loop control, one guard set for the loop, deopt to the tape), and the
call/array rows — 62% of the instruction-weighted gap — are better spent on
compile-time call-site inlining and per-call machinery shrink
(perf/RETRO-2026-11-16.md, ops:userfunc profile).
